# AGENTS

This project provides a Kubernetes controller that creates SPX LoadBalancers (and EIPs for public exposure) from the `LoadBalancer` Services deployed inside a cluster.

## Layout

- `main.go`: flags / env vars (`API_URL`, `API_TOKEN`, `API_ORGA_ID`, `API_AZ`, `DEBUG`), ProjectID discovery from Node annotations, manager setup.
- `controllers/`: `Service` reconciler (LB, EIP, subnet, VIP, finalizer, status).
- `pkg/api/`: HTTP client and types for the SPX public API.
- `chart/spx-lb-controller/`: Helm chart. Its `README.md` is generated by helm-docs from `values.yaml`.
- `.github/workflows/build.yml`: GitHub Actions. Runs the checks below on every PR and push, then builds the image (PRs) and pushes it to GHCR (`ghcr.io/agora-calyce/spx-lb-controller`: `latest` on `main`, chart version on tags). On tags, it also pushes the chart to `oci://ghcr.io/agora-calyce/charts` and creates the GitHub Release with the chart `.tgz` attached. The tag (without leading `v`) must match the chart `version` and `appVersion`.

## Sources

- Clusters, LoadBalancers and EIPs are managed through the SPX API (https://github.com/super-phenix/superphenix/).
- The client calls the public API (`{url}/{orgaId}/api/spx-ctrl/{az}/{projectId}/...`), which proxies to `superphenix-controller`. When checking or changing `pkg/api`, compare against:
  - request bodies, routes and response wrappers: `internal/superphenix-api/pkg/services/controller/{loadbalancer,eip,kaas}/`
  - nested objects (`loadBalancer`, `eip`): `internal/superphenix-controller/internal/models/view/` (the EIP is a kube-ovn `IptablesEIP`)
  - effective ID format (`spx-` + uuidv5(projectId, localId)): `pkg/superphenix-id/`

## Commands

- Build: `go build ./...`
- Lint: `gofmt -l . && go vet ./... && golangci-lint run` (golangci-lint v2) and `go mod tidy` must leave no diff.
- Tests: `go test -race ./...`
- Chart: `helm lint --strict chart/spx-lb-controller`, and `helm-docs --chart-search-root chart` after any change to the chart (CI fails if the chart README is outdated).
- Dockerfile: `hadolint Dockerfile`

## Conventions

- Any code changed, added or removed must have matching tests added or adjusted.
- Code comments, README and generated docs in English. Follow the style of the file you edit.
- Keep `README.md` (annotations, behavior) and `CHANGELOG.md` (`[Unreleased]` section) up to date with functional changes.

## Gotchas

- Never commit any binary / temp file or any secret / credential.
- `CLAUDE.md` is a symlink to `AGENTS.md`: edit `AGENTS.md`.
